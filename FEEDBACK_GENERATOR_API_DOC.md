# Feedback Generator API Documentation

## Base URL
```
http://<host>:8080/api/
```

---

## Endpoints

### 1. Health Check
**GET** `/api/health`

- **Description:** Check if the API service is running.
- **Response Example:**
```json
{
  "status": "healthy",
  "version": "1.0.0"
}
```

---

### 2. Analyze Design
**POST** `/api/analyze`

- **Description:** Analyze design files and generate feedback.
- **Request Body (JSON):**
```json
{
  "files": [
    // List of file data or file paths (format depends on your implementation)
  ],
  "project_type": "string",      // e.g., "Content_writer", "UI/UX_project", etc.
  "description": "string"        // Description of the project
}
```

- **Required Fields:**
  - `files`: List of files to analyze.
  - `project_type`: Type of the project (must match supported types).
  - `description`: Description of the project.

- **Response Example (Success):**
```json
{
  // Feedback result generated by the backend
}
```

- **Response Example (Error):**
```json
{
  "error": "Missing required field: files"
}
```

- **Status Codes:**
  - `200 OK`: Success
  - `400 Bad Request`: Missing or invalid input
  - `500 Internal Server Error`: Unexpected server error

---

## Example Usage

### Health Check
```
curl http://localhost:8080/api/health
```

### Analyze Design
```
curl -X POST http://localhost:8080/api/analyze \
  -H "Content-Type: application/json" \
  -d '{
        "files": ["file1.png", "file2.txt"],
        "project_type": "UI/UX_project",
        "description": "Landing page redesign"
      }'
```

---

## Notes
- Ensure your request JSON matches the required structure.
- The `files` field format depends on your backend’s expectations (file paths, base64, etc.).
- Supported `project_type` values are defined in your backend.
